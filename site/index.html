How it works

Three steps to production-ready geospatial services.

1

Deploy Honua

Deploy to cloud containers or serverless with PostGIS (and Redis for multi-node).

2

Import your data

Import from existing Esri services, files (GeoJSON, Shapefile, GeoPackage, CSV, KML), or existing PostGIS tables.

GeoJSON Shapefile GeoPackage CSV KML
3

Publish services

Expose GeoServices REST FeatureServer, OGC API Features, OData, and Mapbox Vector Tiles (MVT).

Deployment architecture

Single-node without Redis, or multi-node with Redis + PostGIS. Serverless runtimes are supported for event-driven workloads.

Supported runtimes: Azure Container Apps, AWS ECS/Fargate, Kubernetes, Lambda, Azure Functions.

Single-node

Best for evaluation, dev, or small internal apps. Runs Honua + PostGIS.

Clients -> Honua -> PostGIS

Multi-node (production)

Primary production mode: scale-out Honua nodes with shared Redis + PostGIS.

Clients -> LB / Ingress -> Honua (n)
PostGIS + Redis

Serverless runtimes

Run Honua on Lambda or Azure Functions for event-driven workloads and spiky traffic.

API Gateway -> Honua (serverless) -> PostGIS
Redis

Use the same env vars as multi-node deployments.

Getting started

Pick a deployment path and follow the README for a fast, production-ready setup.

Production environments (multi-node/serverless) require Redis for state management. Single-node evaluation works with just PostGIS.

Docker Compose (single node)

Run PostGIS locally without Redis. Best for evaluation and single-node setups.
