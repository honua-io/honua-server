The problem

GIS stacks are expensive, complex, and hard to operate at scale. Example: teams that must support both ArcGIS clients and OGC apps often run two stacks and keep services, auth, and monitoring in sync.

Cost

Duplicated stacks mean duplicated licenses, infrastructure, and deployment pipelines.

Complexity

Upgrades require coordinated downtime, retesting, and republishing services.

Interoperability

Esri vs open standards forces duplication instead of reuse.

Value by audience

One cloud-native server that satisfies business, GIS, and ops teams.

Business & analytics

Use the same data in Power BI, Tableau, and Excel — with editing support through OData and FeatureServer workflows.

Deployment architecture

Single-node without Redis, or multi-node with Redis + PostGIS. AOT builds enable serverless runtimes.

Single-node (no Redis)

Best for evaluation, dev, or small internal apps. Runs Honua + PostGIS; no Redis.

Clients -> Honua -> PostGIS

File storage: local disk or S3/Blob-compatible.

Multi-node (production)

Primary production mode: scale-out Honua nodes with shared Redis + PostGIS.

Clients -> LB / Ingress -> Honua (n)
PostGIS + Redis

Add S3/Azure Blob for imports and attachments.

AOT builds (serverless + containers)

AOT builds improve cold starts and memory footprint for serverless and container platforms.

API Gateway -> Honua (AOT) -> PostGIS
Redis + S3/Blob

Use the same env vars as multi-node deployments.

Getting started

Pick a deployment path and follow the README for a fast, production-ready setup.

Production deployments are multi-node and require PostGIS + Redis. Single-node runs are supported only without Redis.

How it works

Two steps to production-ready geospatial services.

1

Connect + model your data

Point Honua at PostGIS, map layers, and set metadata and auth.

2

Publish + deploy

Expose FeatureServer, OGC, OData, and tiles, then ship to AWS, Azure, or serverless.

Status

MVP supports PostGIS today; additional databases and MapServer export are next.
