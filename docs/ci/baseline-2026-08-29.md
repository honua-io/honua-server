# CI efficiency baseline — 2026-08-29

This is the before-window baseline for the CI efficiency program tracked by
#3204. The observation window is the 14 UTC calendar days from
`2026-08-16T00:00:00Z` through `2026-08-29T23:59:59Z`, inclusive. All data came
from the GitHub Actions REST API through `gh api`; measurement changed no
workflow or repository state.

## Results

| Signal | Population | Result |
|---|---|---:|
| PR Gate workflow duration | 809 completed runs | p50 **18.57 min**, p90 **20.72 min** |
| PR Gate frequency | 809 completed runs / 14 days | **57.79 runs/day** |
| Serving Image Boundary wall time | 393 completed runs | **1,759.83 wall-min/day** |
| Serving Image Boundary cancellation | 279 cancelled / 393 completed runs | **70.99%** |
| `.NET Foundation Tests` job duration | 113 non-skipped job attempts | p50 **37.02 min**, p90 **45.93 min** |
| Full-matrix CI on `trunk` wall time | 28 completed runs | p90 **68.62 min** |
| Claude review lane frequency | 2,207 completed runs / 14 days | **157.64 runs/day** |

Workflow elapsed time is `updated_at - run_started_at`. Job elapsed time is
`completed_at - started_at`. Percentiles use nearest rank after sorting the
observations: rank `ceil(p * n)`. Rates use the fixed 14-day window, including
days with zero runs. Cancelled runs remain in workflow-duration populations;
skipped jobs are excluded from the job-duration population.

“Full-matrix CI on trunk” means `CI` runs with `head_branch == "trunk"`.
This includes 14 scheduled and 14 manually dispatched runs; by `ci.yml` policy,
scheduled runs and non-train dispatches with an empty selective base run the
full lane. “Review lane” means the `Claude Review` workflow, the repository's
named review lane.

The `.NET Foundation Tests` population includes all attempts returned by the
jobs API. This preserves rerun cost and matches the repository's existing
Actions-baseline methodology. During this window the job changed from the
serial test job to the short fan-in job for the parallel family matrix; the
baseline intentionally records the observed mixed before-window population.

## Exact queries

The workflow IDs were resolved first:

```bash
gh api --paginate repos/honua-io/honua-server/actions/workflows \
  --jq '.workflows[] | [.id,.name,.path,.state] | @tsv'
```

The IDs used were `314218576` (`PR Gate`), `325800867` (`Serving Image
Boundary`), `216825513` (`CI`), and `336323786` (`Claude Review`). For PR Gate
and Serving Image Boundary, run this with the corresponding workflow ID:

```bash
gh api \
  'repos/honua-io/honua-server/actions/workflows/<WORKFLOW_ID>/runs?per_page=100&created=2026-08-16T00:00:00Z..2026-08-29T23:59:59Z' \
  --paginate --slurp |
jq '[.[].workflow_runs[] | select(.status=="completed") |
       . + {seconds: ((.updated_at|fromdateiso8601) -
                       (.run_started_at|fromdateiso8601))}] |
    sort_by(.seconds) |
    {n:length, runs_per_day:(length/14),
     cancelled:(map(select(.conclusion=="cancelled"))|length),
     cancellation_rate:((map(select(.conclusion=="cancelled"))|length)/length),
     wall_minutes_per_day:(map(.seconds)|add/60/14),
     p50_minutes:(.[((length*0.50|ceil)-1)].seconds/60),
     p90_minutes:(.[((length*0.90|ceil)-1)].seconds/60)}'
```

The full-matrix trunk query was:

```bash
gh api \
  'repos/honua-io/honua-server/actions/workflows/216825513/runs?per_page=100&created=2026-08-16T00:00:00Z..2026-08-29T23:59:59Z' \
  --paginate --slurp |
jq '[.[].workflow_runs[] |
       select(.status=="completed" and .head_branch=="trunk") |
       . + {seconds: ((.updated_at|fromdateiso8601) -
                       (.run_started_at|fromdateiso8601))}] |
    sort_by(.seconds) |
    {n:length, p90_minutes:(.[((length*0.90|ceil)-1)].seconds/60),
     events:(group_by(.event) |
             map({key:.[0].event,value:length}) | from_entries)}'
```

The Foundation job query used the repository's read-only collector to fetch all
job attempts, followed by an upper-window filter because `--created-after` is
lower-bound-only:

```bash
python3 scripts/ci/measure-actions-baseline.py \
  --workflow ci.yml --created-after 2026-08-16 --limit 100 --api-workers 8 \
  --input-out /tmp/honua-ci-baseline-input.json.gz \
  --json-out /tmp/honua-ci-baseline.json --format json

gzip -dc /tmp/honua-ci-baseline-input.json.gz |
jq '[.workflows[0].runs[] |
       select(.created_at >= "2026-08-16T00:00:00Z" and
              .created_at < "2026-08-30T00:00:00Z") |
       .jobs[] |
       select(.name==".NET Foundation Tests" and
              .conclusion!="skipped" and
              .started_at!=null and .completed_at!=null) |
       ((.completed_at|fromdateiso8601) -
        (.started_at|fromdateiso8601))] |
    sort |
    {n:length, p50_minutes:(.[((length*0.50|ceil)-1)]/60),
     p90_minutes:(.[((length*0.90|ceil)-1)]/60)}'
```

The review lane exceeded GitHub's 1,000-result cap for a single Actions run
search. The exact count therefore used one bounded query per UTC day:

```bash
for day in $(seq 0 13); do
  start=$(date -u -d "2026-08-16 +${day} days" +%Y-%m-%dT00:00:00Z)
  end=$(date -u -d "2026-08-16 +$((day+1)) days -1 second" \
    +%Y-%m-%dT%H:%M:%SZ)
  gh api \
    "repos/honua-io/honua-server/actions/workflows/336323786/runs?per_page=100&created=${start}..${end}" \
    --paginate --slurp |
    jq '[.[].workflow_runs[] | select(.status=="completed")] | length'
done | jq -s '{daily_counts:.,n:add,runs_per_day:(add/14)}'
```

The daily counts were `0, 30, 63, 13, 15, 195, 127, 208, 204, 328, 401,
156, 208, 259`. Their sum is 2,207.
