# Cloud-Native-Geospatial (CNG) Conformance — Status

Last reviewed: 2026-06-20
Owner: Honua Server platform

This page records how honua's **produced** cloud-native-geospatial artifacts are
validated against the canonical, first-party validators, and which formats are
intentionally out of scope. The functional lane lives at
[`.github/workflows/cng-conformance.yml`](../.github/workflows/cng-conformance.yml),
the runner at [`scripts/conformance/cng/run-cng-conformance.sh`](../scripts/conformance/cng/run-cng-conformance.sh),
the store-backed seed/compose under [`docker/cng/`](../docker/cng/), and the
artifact generator under
[`scripts/conformance/cng/artifact-gen/`](../scripts/conformance/cng/artifact-gen/).

## Gated formats

The lane fails CI if any validator exits non-zero against honua's real output.

| Format | honua surface | How it is produced for the lane | Canonical validator |
|---|---|---|---|
| **GeoParquet 1.1.0** | FeatureServer / MapServer `f=parquet` | Fetched live from the store-backed `cng` FeatureServer (`f=parquet`) | [`gpq validate`](https://github.com/planetlabs/gpq) |
| **FlatGeobuf** | FeatureServer `f=fgb` | Fetched live from the `cng` FeatureServer (`f=fgb`) | GDAL `ogrinfo -al -so` with `OGR_FLATGEOBUF_VERIFY_BUFFERS=YES` (no dedicated validator exists) |
| **PMTiles v3** | `GET /api/v1/tiles/pmtiles/{artifactId}` | Generated by driving honua's `PMTilesWriter` | [`pmtiles verify`](https://github.com/protomaps/go-pmtiles) |
| **3D Tiles 1.1** | `/scenes/.../tileset.json` (+ GLB content) | Generated by driving honua's `TilesetDocumentWriter` + `GeometryTileBuilder` | [`3d-tiles-validator`](https://github.com/CesiumGS/3d-tiles-validator), which chains the Khronos [`gltf-validator`](https://github.com/KhronosGroup/glTF-Validator) |

### Store gating note (why a dedicated `cng` service exists)

The default `test` / `browser_compat` services historically returned
`HTTP 400 "Output format ... is not supported by the configured feature store"`
for `f=parquet` / `f=fgb`. The FeatureServer query handler gates those formats on
the resolved feature store implementing the `IFlatGeobufFeatureStore` /
`IGeobufFeatureStore` marker interfaces (see
`FeatureServerQueryExecutor.V2.SupportsFlatGeobufOutputAsync`). The canonical
PostgreSQL store (`PostgresFeatureStoreRefactored`) implements those markers and
the shared `GeoParquetFeatureWriter`, so a PostgreSQL-backed layer serves both
formats. The lane seeds an additive, store-backed `cng` FeatureServer
(`docker/cng/seed.sql`, layer 1000 over the `features` table) so the
cloud-native export paths are exercisable end to end without disturbing the
existing test services.

## Carve-outs (intentionally NOT gated)

honua consumes/transcodes these formats but does not PRODUCE conformant output,
so gating a first-party producer-validator against them would be meaningless:

- **COG** — `exportImage` emits a plain GeoTIFF; `format=cog` is rejected. honua
  reads COG, it does not author cloud-optimized GeoTIFF output.
- **Zarr / GeoZarr** — read / transcode only.
- **COPC** — read / transcode only.

## Local validation evidence (2026-06-20)

Running honua's writers through their canonical validators on the produced
artifacts:

- GeoParquet (`GeoParquetFeatureWriter`): `gpq validate` — **Passed 20 checks**.
- PMTiles v3 (`PMTilesWriter`): `pmtiles verify` — **exit 0**.
- 3D Tiles GLB (`GeometryTileBuilder`): Khronos `gltf_validator` —
  **Errors: 0, Warnings: 0**.
- FlatGeobuf (`f=fgb`): validated in CI via `ogrinfo` read-back (Postgres-native
  producer, no pure-managed writer to exercise offline).
