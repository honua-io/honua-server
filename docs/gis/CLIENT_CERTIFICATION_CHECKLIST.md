# QGIS and PyQGIS compatibility checklist

This checklist records the remaining QGIS and PyQGIS interoperability review, open
coverage work, and evidence requirements. Its machine-readable projection is
[`data/client-certification-checklist.v1.json`](data/client-certification-checklist.v1.json),
generated by `scripts/certification/build-client-checklist.py`.

The current certification target is QGIS 3.44.14 LTR and its bundled PyQGIS
version. Earlier client-specific evidence and license records are outside this
checklist. The generated tables below contain only the two active QGIS lanes.

## Evidence owner

The [QGIS and PyQGIS inventory](https://github.com/honua-io/honua-client-compat)
tracks provider behavior, algorithms, authentication, and workflow review. This
repository records server-side contract coverage and open integration work.

## Target lanes

| Lane | Build | Evidence owner |
|---|---|---|
| `qgis-ui` | QGIS 3.44.14 LTR | QGIS and PyQGIS inventory; UI workflows |
| `pyqgis` | PyQGIS bundled with QGIS 3.44.14 LTR | QGIS and PyQGIS inventory; Python workflows |

Preview and experimental server features remain on a separate readiness track.
Certification cells report operation-specific outcomes, with evidence required
for passes, exclusions, failures, and blocked work. A disabled menu, missing
provider, failed URL, timeout, or empty result alone does not establish a cause;
review alternate client paths and independent controls before recording a result.

### Customer-readiness goal

Demonstrate that customers can reliably use Honua's advertised supported workflows in QGIS, PyQGIS, desktop client and desktop Python client on declared client versions and license profiles. Reconcile the client surface into one traceable matrix, repair server and harness defects, and pass every required native workflow and regression gate against the same frozen shipping NativeAOT/Production candidate. Publish reproducible setup instructions, evidence and precise limitations. Accept documented client exclusions and licensed skips only within their stated profile; keep preview/experimental readiness separate.
