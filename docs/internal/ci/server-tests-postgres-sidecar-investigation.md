**Why the private containers remain:**

- **Core and Cloud Contracts:** [`ClientCompatSeedSequenceTests`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.Server.Tests/Seed/ClientCompatSeedSequenceTests.cs#L24) (two cases) and [`CompatCompileBindingAndAccessPolicyTests`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.Server.Tests/Seed/CompatCompileBindingAndAccessPolicyTests.cs#L109) (one case) unconditionally create private PG16/PostGIS containers, despite the URL. Their `pg_isready` database names are `honua_seed_regression`, `honua_seed_binding_regression`, and `honua_compat_compile_regression`. The image is already local from sidecar startup. The same shard also uses the sidecar through other fixtures. [`client-compat-v1.sql`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/seed/client-compat-v1.sql#L9) creates fixed `honua.*` and unqualified `features` objects: substituting the shared connection string risks contamination and incorrect seed baselines. A future (b) could use dedicated databases on the sidecar with explicit creation/cleanup and validation of pristine seed state. That is more than one line.
- **GeoServices Geometry VectorTile and Versioning:** [`DatumGridPostgresFixture`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.TestKit/DatumGridPostgresFixture.cs#L22) intentionally pins `postgis/postgis:18-3.6@sha256:60f6ad1d21ea86a67d47780b9a0d1e1d200500f62b19293fa834d0dea80b8677`, a private PROJ data directory, network-off operation and grid-present/grid-absent profiles. Both runs boot five private databases. The PG16 sidecar cannot replace this runtime/filesystem isolation without changing the datum tests' meaning. The shard's ordinary endpoint tests still use the sidecar.
- **Operator Eval Harness:** only A includes the newly added [`PostgisSourceExecutionProofTests`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.Server.Tests/Features/Geoprocessing/Execution/PostgisSourceExecutionProofTests.cs#L20), which boots PG17 for `external_survey`. B predates this file. The test requires the source table to exist only in the second database, distinct from the Honua catalog; replacing it with the shared catalog connection would weaken the proof. A dedicated sidecar database may be a future design, but requires preserving distinct credentials, registration, database isolation and cleanup.

The common [`PostgresFixture.InitializeAsync`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.TestKit/PostgresFixture.cs#L47) **already** reads `HONUA_TEST_DB_URL` and branches around `PostgreSqlBuilder`/`StartAsync` when set. [`WebAppFixture`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.TestKit/WebAppFixture.cs#L145) initializes that fixture. This path is unchanged between the two sampled heads. There is no missing one-line URL assignment to fix. [`GP Devkit CLI's project`](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.Geoprocessing.Cli.Tests/Honua.Geoprocessing.Cli.Tests.csproj) instead declares offline tests with no TestKit dependency; its [end-to-end cases](https://github.com/honua-io/honua-server/blob/a7b5827d7ad8347a36714e5858e94046129312f9/tests/dotnet/Honua.Geoprocessing.Cli.Tests/GpCliEndToEndTests.cs#L10) execute managed operations without a database. Source inspection of its seven executed test classes found no database URL/fixture consumer.

Observed Δ-first medians were **2.81 / 2.72 s**, ranges **0.48–7.26 / 0.54–6.88 s**. These short intervals do not imply that subsequent fixture setup is free. Removing GP Devkit CLI's service has **no demonstrated full-matrix critical-path saving**: it is not the slowest shard. The measurable opportunity is roughly 22 seconds of that job's startup/resource use, with actual billing effects dependent on runner-minute rounding and scheduling. There is no evidence supporting removal of the sidecar from the three mixed-use shards.

**Disposition:** choose (a) for GP Devkit CLI only; retain all other sidecars and isolated PostGIS tests. Leave any per-test database reuse to an owner-approved implementation with isolation validation.
