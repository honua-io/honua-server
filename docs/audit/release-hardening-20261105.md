## Migration 145 compatibility boundary

Replacement now uses RESTRICT within the same atomic promotion transaction. Ownership checks still apply; dependent objects cause a stable sanitized failure and preserve the original target. The forward migration only executes `CREATE OR REPLACE` with the existing helper signature; its deferred destructive statements do not run during installation.

The classifier uses the existing exact-name/SHA reviewed-function-definition mechanism, with mutation and appended-DDL rejection tests. This does not make the old binary compatible: its older classifier rejects the deferred DDL. Migration 145 therefore explicitly declares reader incompatibility. **Coordinate the server/worker upgrade; restore the matching pre-upgrade database backup and image for rollback. Older images will not serve the upgraded database.**

Final SQL SHA256 is `5137ECDF8A2C23C7503B048BA79EA21CF504B89DED7E0E5A64417724D7DEAEB1`, matching the certification ledger and classifier registry. Final `f17f1a1a03` N-1 artifact `13481977813` confirms expected refusal with exit zero: prior schema-143 image refuses declared reader-incompatible migrations 144/145 with `schema_reader_incompatible`, without changing the journal. The generic classifier and N-1 probe were not weakened. All sixteen changed blobs, including deployment guidance, landed unchanged at `53011a5646`.

The reviewed trunk update `be656f62ff` changes license headers in thirteen existing migrations without changing executable SQL. The classifier retains the updated exact hash for migration 129 and the final exact hash for 145.
