# 2026.1-rc.2 identifier changes

This release candidate makes intentional breaking identifier changes before the first supported server release. Update integrations against the matching server contract and client versions. Earlier evaluation-build compatibility results do not qualify these changes.

The [Layer glossary](../../concepts/domain/layer.md) defines `storageLayerId`, `serviceLayerIndex`, and the graph Layer ID. For example, storage handle `41`, Service-local index `3`, and graph ID `roads:primary` can identify the same exposed Dataset. Rebinding that Layer to storage handle `73` preserves its public identity.

| Surface | Previous identifier | Identifier in rc.2 |
| --- | --- | --- |
| Connection-scoped layer administration | `layerId` | `storageLayerId` |
| Global `/api/v1/admin/metadata/layers` routes | Ambiguous `layerId`, sometimes resolved as a Service-local index | `storageLayerId`, resolved explicitly through the storage binding |
| Service-scoped layer administration | `layerId` | `serviceLayerIndex`, scoped by the Service |
| MCP query, map, style, discovery, and entity-resolution contracts | `layerId` | `serviceLayerIndex`, with the associated Service |
| WFS feature type local name | Resource name with a storage-derived suffix | Graph Layer ID encoded as an XML NCName |
| Service-scoped WMS layer name | Resource name or storage handle | The Layer's Service-local `Identifier.Value` |
| OGC API Records layer record ID | `layer:{storageLayerId}` | `layer:{graph Layer ID}` |
| Public MapLibre style route | `/api/styles/{layerId}.json` with an integer selector | `/api/styles/{publicationId}.json` with the graph Layer ID |

Global metadata administration no longer substitutes a Service-local index for a storage handle. If multiple distinct Dataset resources claim the same storage handle, configuration writes fail as ambiguous rather than selecting one resource. SDK clients should regenerate against the updated OpenAPI parameter and model names.

MCP clients must send `serviceLayerIndex`, including entries in `render_map.layers`. Discovery and entity resolution return the explicit Service-local selector. The affected tools are `query_features`, `render_map`, `get_style`, `apply_style_preset`, `list_layers`, and `resolve_entity`.

WFS uses the reversible `XmlConvert.EncodeLocalName` encoding of the graph Layer ID. Decode the advertised local name with the corresponding XML name decoder to recover the graph ID. Encoding preserves distinctions between IDs containing punctuation and IDs containing literal escape-shaped text. Different Services can both expose index `0` while retaining distinct WFS feature types through their globally unique graph IDs.

Use the identifiers advertised by capabilities, discovery, and record links. Storage handles are no longer accepted as public protocol aliases. Public style requests resolve the current storage binding of the identified Layer.
